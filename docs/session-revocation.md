# Завершение других входов — разработка, не релиз

Кнопка «Безопасность аккаунта» завершает **другие действующие сессии** этой учётной записи. Текущая сессия остаётся действительной; список устройств и удалённое завершение отдельного устройства не реализованы. Пароль проверяется повторно; запрос требует текущую действительную сессию, правильные Origin, JSON и CSRF. По завершении пароль не меняется: им можно войти снова с любого устройства. Вход, которому пароль был проверен до операции, не может выдать новую сессию после неё; вход, завершившийся раньше, отзывается.

Операция меняет `recovery_generation`: **все ранее выданные, ещё не использованные ссылки сброса пароля перестают действовать**, как сообщается пользователю до подтверждения. Новый запрос восстановления может быть временно ограничен действующим 10-минутным интервалом. Сама миграция 0033 не меняет данные или активные сессии: это происходит только при успешной операции. Регистрация и восстановление в production пока отключены.

Граница гарантии: запросы, которые уже прошли проверку сессии до отзыва, могут завершиться после него — прекращение чужих запросов в процессе не гарантируется. Сессии, проверенные после фиксации отзыва, отклоняются; чужие данные, закэшированные на устройстве, не стираются. Если ответ потерян, действие могло выполниться: клиент рекомендует проверить вход на других устройствах до повтора. Для компрометации пароля необходим также сброс/смена пароля, когда безопасное восстановление доступно; одна эта кнопка не защищает от повторного входа с известным паролем.

Реализация сериализует выдачу сессий, отзыв и сброс пароля блокировкой пользователя; ещё раз проверяет текущую сессию, её срок и поколение пароля под блокировками. Роль runtime может вызвать функцию, но не менять поколение напрямую; доверие к самой роли API и защита от компрометации сервера остаются необходимыми. Ограничение попыток — пять за 15 минут на IP в процессе, **не распределённое**; за прокси необходима предварительно спроектированная проверенная политика client-IP и общих лимитов. Вход, отзыв и уже начатые запросы могут завершиться ошибкой при конфликтах блокировок; целостность транзакции сохраняет PostgreSQL.

Для развёртывания требуется согласованная миграция 0033, новый API и клиент: проверка точного журнала схем намеренно не позволяет старой и новой версиям API одновременно работать на одной схеме. Нужны окно обслуживания, резервная копия, проверенный план восстановления и сверка точных версий. Новый клиент со старым API не предоставляет эту функцию. Действующий demo и ранее выданный APK не обновлялись. Настоящие Android WebView, iOS и production-сеть этим тестом не проверены.

Для воспроизводимой проверки только на выделенном тестовом PostgreSQL используется `tests/run-sessions-live.py` с явным `ALLOW_DISPOSABLE_DATABASE=yes` и тестовыми переменными; runner отказывается перезаписывать одноимённую базу, создаёт и удаляет лишь собственную. Тест использует синтетические аккаунты, изоляцию, ошибки подтверждения, Origin/CSRF, ограничения, истечение и контролируемые параллельные транзакции. Browser synthetic HTTPS проверяет форму и реальные cookie через тестовый gateway, но не представляет реальный Android/iOS или аудит безопасности.
