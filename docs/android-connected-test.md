# Android: изолированный эксперимент совместного режима

Это **не готовая и не распространяемая сборка**. Она предназначена только для вымышленных данных и адреса HTTPS с доменом `.test`; такого развёрнутого сервера и доверенного Android сертификата здесь не предоставлено. Ни реальные аккаунты, ни демо-пароли не встраиваются в APK. Публичный сервис и полноценный совместный Android APK не готовы.

## Что сделано

По умолчанию прежний сценарий собирает автономный вариант без `INTERNET`, с прежним package ID, `versionCode=1` и локальным origin `https://appassets.androidplatform.net`. Изменять локальные данные или автоматически переносить их не требуется.

Явный вариант `connected-test` запрашивает `INTERNET` и имеет `versionCode=2`. Локальный экран и его хранилище остаются на прежнем origin, там же остаётся мост экспорта JSON. Кнопка открывает второй WebView, изолированный от локального по origin, без интерфейсов `AndroidBackup` и `AndroidOnline`. Он загружает исходную оболочку сервера и открывает в ней раздел «Вместе онлайн», а не отдельный отклонённый ранее облачный интерфейс. Кнопка сверху возвращает к локальному экрану без объединения данных. Выход из второго экрана не выполняет выход из учётной записи; для него есть отдельная кнопка в интерфейсе. Семейный серверный график требует подтверждённого аккаунта владельца графика и его разрешения.

Адрес заранее задаётся при сборке и допускает только синтетический `.test` HTTPS-origin без пути, логина, параметров и фрагмента. Внешние адреса нельзя подставить через JS-мост. Сетевая страница работает на **своём** серверном origin, поэтому сессионная cookie и CSRF остаются однодоменными, а не передаются через JavaScript или сторонний bearer. Сервер обязательно должен отдавать проверенный исходный интерфейс и API с этого же HTTPS-origin; доверие к содержимому сервера и его XSS-защита здесь критичны. `allowFileAccess`, mixed content, новые окна и сторонние cookies отключены, стандартная проверка TLS не обходится. Навигация ограничена несколькими точными путями этого origin. Прямые запросы на другой origin отклоняются в `shouldInterceptRequest`.

В экспериментальном APK добавлен приём только HTTPS-ссылок приглашений для заданного при сборке `.test`-домена и корневого пути. Код отдельно проверяет origin, порт и формат единственного фрагмента `community-invite` или `trip-invite`; посторонние адреса, пути, query и смешанные фрагменты отклоняются. При открытии показывается нативное подтверждение, а вступление отдельно подтверждается на серверной странице после входа. Ссылка не переносит локальные данные. Токен находится во фрагменте входной ссылки, а обновлённый интерфейс передаёт его в JSON-теле запросов preview/redeem, не в URL. В test/development старые API-маршруты для прежних клиентов по-прежнему содержат токен в пути, а в production они отключены: прежний клиент необходимо обновить. Ссылки с фрагментом для текущего клиента не изменились. API теперь возвращает их сразу; новый интерфейс также понимает старый ответ `/join/…`, но старый интерфейс новый ответ может не обработать. Обновление API и интерфейса должно быть согласованным. Прокси, сервер и мониторинг обязаны не сохранять тела, секреты и старые URL в логах; исключить утечки через аналитические инструменты и записи SQL-параметров. Android и отправившее приложение могут сохранять исходный intent; нельзя обещать, что токен нигде вне приложения не останется.

Фильтр `VIEW`/`BROWSABLE` и `singleTask` есть только в synthetic-варианте, без `autoVerify`; проверенных Android App Links и файла assetlinks нет. Выбор приложения системой, переход из мессенджера, запуск закрытого приложения, `onNewIntent`, отмена диалога, повторные ссылки, поворот и работа после выгрузки **на устройстве не проверены**. Это не готовый механизм внешних ссылок для реальных пользователей.

**Это не полная изоляция сети:** Android WebView может не вызывать перехват для последующих URL в цепочке перенаправлений и ряда специальных схем; на это ограничение нельзя полагаться как на firewall. Нужны сервер без внешних redirect, строгий CSP, отдельная проверка service worker, навигаций и реальной сетевой модели. CSS-скрытие локальных разделов на удалённой странице — только UI, не граница безопасности. В локальной оболочке и gateway inline-скрипты запрещены, а inline-стили пока разрешены; это не заменяет независимую проверку XSS и реального Android WebView. Регистрация и восстановление, ссылки-приглашения из других приложений, системное открытие файлов, отказ сети, длительная сессия, сертификаты, обработка поворота и обновление Android-приложения с сохранением данных на устройстве пока не проверены и не должны считаться готовыми.

## Сборка для разработки

Нужны JDK 17, Android SDK Platform 35 и Build Tools. Тот же приватный тестовый ключ, что и у автономной сборки, используется исключительно для будущей проверки обновления; он не релизный. Сборка не должна отправляться пользователю до полной проверки.

```sh
export JAVA_HOME=/path/to/jdk17
export ANDROID_SDK_ROOT=/path/to/android-sdk
export SOBRALIS_ANDROID_VARIANT=connected-test
export SOBRALIS_ANDROID_TEST_ORIGIN=https://sobralis.example.test
scripts/build-android-offline.sh android/build/android-connected-isolated.apk
```

При отсутствии явно выбранного варианта скрипт создаёт автономный APK. Для подключённого варианта `http`, реальные домены, IP, адреса с путём, учётными данными или явным стандартным портом `:443` отвергаются сборщиком и проверяются ещё раз при запуске. Для физического синтетического стенда потребуется настроить соответствующие DNS и доверенный Android TLS, не отключая проверку сертификата. Нельзя направлять эту экспериментальную сборку на настоящие данные.

## Что проверено и чего нет

Собраны оба варианта, проверены разрешения, package ID, версии, ресурсы, zipalign, подписи и совпадение тестового сертификата с ранее установленным автономным APK. Чистый Java-тест проверяет точное сопоставление origin, портов, путей и попытки подмены. Chromium-симуляция проверяет локальную семью, открытие исходной онлайн-оболочки, вход на синтетический demo и отсутствие доступа удалённой страницы к подставленным мостам, не изменяя локальное хранилище.

Дополнительно `tests/run-android-https-live.py` создаёт **новую одноразовую** `sobralis_android_https_test`, мигрирует её и запускает `tests/browser-android-https.cjs`: через `infra/site-gateway.cjs` за временным HTTPS-терминатором без demo bearer проверены настоящая cookie `Secure`, `HttpOnly`, `SameSite=Strict`, вход, повторное открытие, выход и отзыв сессии, запрет чужого Origin и отсутствующего CSRF, закрытые маршруты регистрации и восстановления, приглашения в сообщество и поездку, повтор создания поездки после ответа 503 уже после записи (в том числе перезагрузка, недоступное хранилище и смена аккаунта), предоставление и отзыв доступа к семейному графику, сохранение отмеченных дней и раздельность локального хранилища. Используются только вымышленные аккаунты; БД после теста удаляется. Обязательны `ALLOW_DISPOSABLE_DATABASE=yes`, тестовые `DB_HOST`, `DB_PORT`, `TEST_ADMIN_PASSWORD`, `TEST_MIGRATOR_PASSWORD`, `TEST_RUNTIME_PASSWORD`, отдельно установленный Playwright в `NODE_PATH`, сборка backend и `connected-test` assets. Скрипт откажется создавать БД, если имя уже занято; никогда не направляйте его на рабочий сервер.

Сертификат и ключ генерируются на время теста. Chromium принимает только искусственно закреплённый тестовый SPKI, а отдельные негативные HTTP-запросы намеренно отключают проверку тестового сертификата. Это проверка прохождения зашифрованных запросов и логики cookie в Chromium, **не** проверка обычного доверия к TLS и не воспроизводит Android WebView, Android cookie, сетевой перехват или взаимодействие с ОС. Демо-симуляция выше использует отдельный bearer-мост и не является частью этого HTTPS-теста.

Физический запуск этой версии и установка поверх ранее выданного APK не проводились; эмулятор Android недоступен. До передачи пользователю необходимо обеспечить отдельный тестовый сервер с корректными HTTPS и маршрутизацией, проверить обычную cookie-сессию, ссылки и доступы, сохранность обоих origin при обновлении и нештатных ситуациях, перепроверить угрозы и выполнить всю проверку на разных версиях Android. Для выхода за `.test` потребуется отдельный осознанный пересмотр конфигурации, сетевой политики и безопасности, а не простое снятие ограничения.
